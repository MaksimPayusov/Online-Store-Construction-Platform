# Система ролей

## Описание

В проекте реализована система из трех ролей:
- **admin** - администратор (может назначать других админов)
- **owner** - владелец магазина
- **user** - обычный пользователь (назначается по умолчанию при регистрации)

## Регистрация

При регистрации нового пользователя через `/auth/register` автоматически назначается роль **user**.

## Назначение ролей

Для назначения роли используется эндпоинт:
```
POST /auth/assign-role
Headers:
  X-User-Id: <ID текущего пользователя>
Body:
  {
    "targetUserId": "<ID пользователя, которому назначается роль>",
    "roleName": "admin|owner|user"
  }
```

**Важно:** Только пользователи с ролью **admin** могут назначать роль **admin** другим пользователям.

## Получение ролей пользователя

```
GET /auth/user/{userId}/roles
```

## Роль в заголовках

Фильтр `RoleHeaderFilter` автоматически извлекает роль из JWT токена (из заголовка `Authorization: Bearer <token>`) и добавляет её в заголовок ответа:
- `X-User-Role: admin|owner|user`

Роль определяется по приоритету: admin > owner > user (если у пользователя несколько ролей, выбирается наивысшая).

## Структура JWT токена

Keycloak помещает роли в токен в следующем формате:
```json
{
  "realm_access": {
    "roles": ["user", "admin", ...]
  }
}
```

Фильтр извлекает роль из `realm_access.roles` и добавляет её в заголовок.
